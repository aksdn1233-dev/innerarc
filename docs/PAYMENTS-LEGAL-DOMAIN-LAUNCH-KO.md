# InnerArc 결제·법률·운영 도메인 출시 체크리스트

기준일: 2026-07-31
상태: 페이앱 자동결제와 계좌입금 방식을 모두 구현. 결제가 닫혀 있는 이유는 관리자 화면에서 항목별로 확인하고 그 자리에서 열 수 있다

이 문서는 개발·운영 준비용 체크리스트이며 개별 법률자문을 대신하지 않는다. 실제 계약과 판매자 정보를 기준으로 최종 검토해야 한다.

## 1. 구현된 판매 흐름

- 현재 판매 상품은 사주 원국 5,500원, 상세 리딩 39,000원, 프리미엄 심층 리딩 79,000원이다. 기존 핵심 리딩 19,000원 주문과 저장 리포트는 역사 호환성만 유지한다.
- 무료 결과는 제공하지 않는다. `상품 선택 → 상품별 정보 입력 → 결제 → 서버 승인 → 리포트` 순서다.
- 로그인은 선택이다. 비회원은 고강도 임의 토큰으로 보호된 전용 리포트 주소에서 열람·다운로드하고, 회원 구매는 마이페이지에도 보관한다.
- 리포트는 PC와 휴대폰에서 열고 HTML 파일로 내려받거나 브라우저 인쇄 메뉴에서 PDF로 저장할 수 있다.
- 사주 원국의 `이메일로 받아보기`는 구매자가 자신의 기본 메일 앱으로 보호된 리포트 주소를 보내는 명시적 동작이다. 서비스가 이메일 주소를 수집하거나 자동 발송하지 않는다.
- 회원은 마이페이지에서 주의사항 알림, 화면 알림, 이메일 알림 신청을 각각 켜거나 끌 수 있다.
- 이메일 발송 자체는 승인된 메일 발송 사업자와 발신 도메인이 연결된 뒤 활성화한다.

## 2. 결제 구조

- 현재 기본 경로는 페이앱(PayApp) 호스티드 결제창이다. 서버가 페이앱 API로 결제요청을 만들고, 사용자는 페이앱이 발급한 `*.payapp.kr` HTTPS 주소에서 결제한다.
- 페이앱 결제결과는 서버 대 서버 피드백으로 확인한다. 브라우저 복귀만으로는 리포트를 열지 않는다.
- 대체 경로는 사업용 계좌 직접 입금이다. 주문자가 입금자명을 입력하면 계좌·금액·기한을 안내하고, 관리자가 실제 입금 내역을 확인한 뒤 해당 주문의 리포트를 연다.
- 이 방식은 은행이 주문마다 발급하는 `가상계좌`가 아니라 일반 `계좌입금`이다. 자동 입금 통보가 없으므로 관리자 확인 전에는 리포트를 열지 않는다.
- 포트원 V2와 KPN 채널도 대체 경로로 유지한다.
- 계약·심사가 끝난 범위에서 카카오페이, 토스페이, 카드, 가상계좌를 노출한다.
- 기존 토스페이먼츠 V2 어댑터는 대체 경로로 유지한다.
- 활성 상품과 금액은 서버 카탈로그와 환경변수가 정확히 일치해야 하며 브라우저 입력 금액을 신뢰하지 않는다. 기존 가격이 남아 있으면 결제를 닫아 잘못된 금액 청구를 막는다.
- 성공 리다이렉트와 웹훅 모두 결제사 API를 다시 조회해 주문번호, 스토어, 통화, 금액, 상태를 검증한다.
- 가상계좌는 `WAITING_FOR_DEPOSIT`에서 리포트를 열지 않는다. 조회 결과가 `DONE`일 때만 생성한다.
- 결제 취소·환불이 접수되면 회원은 데이터베이스 함수가, 비회원은 콜백 처리가 리포트 접근을 회수한다.
- 시크릿키, 웹훅 시크릿, 서비스 역할 키는 서버에서만 사용한다.

## 2-0. 결제가 막혔을 때 가장 먼저 볼 곳

`https://운영도메인/ko/admin` 의 **결제 열림 상태** 패널이 결제를 막고 있는 조건을 항목별로 보여준다. 결제 경로, 연동 값, 노출 결제수단, 판매 금액, 데이터베이스, 운영 도메인, 관리자 계정, 신규 결제 접수를 각각 정상·필요·오류로 표시하고, 고쳐야 할 환경변수 **이름**과 다음 행동 한 줄을 함께 낸다. 값 자체는 절대 표시하지 않는다.

같은 패널에서 **최근 결제사 오류**로 페이앱이 결제요청을 거부했을 때 페이앱이 보낸 문구를 그대로 확인할 수 있다. 판매자 심사 대기, 등록되지 않은 주소처럼 코드가 아니라 가맹점 쪽에 원인이 있는 경우를 여기서 바로 구분한다.

`https://운영도메인/api/health` 는 로그인 없이 `status`, `site`, `database`, `payments` 네 값만 돌려준다. 화면을 고치는 중에도 서비스와 결제가 살아 있는지 한 번에 확인하거나 외부 감시 도구에 연결할 때 쓴다. 비밀값·매출·주문 수는 담지 않으며 항상 HTTP 200으로 응답한다.

필수 운영 환경변수:

- 모든 운영 결제 경로 공통:
  - 별도의 판매 개시 승인 단계는 없다. 선택한 결제사, 올바른 연동 값,
    데이터베이스, HTTPS 운영 주소와 코드 카탈로그가 정상이면 결제가 바로 열린다.
  - 관리자 화면의 신규 판매 중지는 장애 대응용이다. 이미 시작된 결제의 결과
    콜백은 판매 중지 여부와 관계없이 계속 받아 결제 상태가 유실되지 않게 한다.
- 페이앱 경로(현재 기본):
  - `PAYMENTS_PROVIDER=payapp`
  - `PAYAPP_USER_ID` — 페이앱 판매자 아이디
  - `PAYAPP_LINK_KEY` — 페이앱 관리자 > 연동 정보의 연동 KEY
  - `PAYAPP_LINK_VALUE` — 같은 화면의 연동 VALUE
  - `PAYAPP_OPEN_PAY_TYPES` — 기본값 `card,kakaopay,tosspay,vbank,phone,rbank`
- 즉시 계좌입금 경로:
  - `PAYMENTS_PROVIDER=manual_transfer`
  - `MANUAL_BANK_NAME`
  - `MANUAL_BANK_ACCOUNT`
  - `MANUAL_BANK_HOLDER`
  - `MANUAL_DEPOSIT_WINDOW_HOURS=24`
- PG 승인 후 자동결제 경로:
- `PAYMENTS_PROVIDER=portone`
- `PORTONE_STORE_ID`
- `PORTONE_KPN_CHANNEL_KEY`
- `PORTONE_API_SECRET`
- `PORTONE_WEBHOOK_SECRET`
- 판매 금액 — `INNERARC_COMPREHENSIVE_PRICE_KRW`, `INNERARC_PREMIUM_PDF_PRICE_KRW` 는 **선택**이다. 실제 판매 금액은 `src/core/product-prices.ts` 카탈로그가 가진다. 값을 넣으면 “이 배포는 카탈로그와 같은 금액을 판다”는 선언이 되어, 다르면 결제를 닫아 잘못된 금액 청구를 막는다. 비워 두면 카탈로그 금액이 그대로 적용된다. 가격을 바꿀 때 과거 값이 남아 결제가 통째로 닫히는 일을 피하려면 비워 두는 편이 안전하다.
- `ADMIN_EMAILS` — 쉼표로 구분한 관리자 로그인 이메일
- Supabase URL, publishable key, service-role key

페이앱 피드백 URL은 `https://운영도메인/api/payments/payapp/feedback`이다. 이 주소가 공개망에서 접근 가능해야 결제 승인이 반영된다. 페이앱은 응답 본문이 정확히 `SUCCESS`가 아니면 재시도하므로, 실패 응답을 삼키지 않는다.

포트원 웹훅 URL은 `https://운영도메인/api/payments/portone/webhook`이다. KPN 가상계좌 입금통보 URL에도 같은 운영 주소를 등록하고 실제 입금 테스트를 해야 한다.

## 2-1. 비회원 리포트 접근

비회원 주문의 유일한 열람 수단은 리포트 주소에 포함된 임의 토큰이다. 결제 진행 화면에서 이 주소를 먼저 보여주고 복사할 수 있게 하며, 같은 브라우저의 로컬 저장소에도 45일간 보관한다. 저장하는 값은 리포트 주소와 저장 시각뿐이고 생년월일·이름·고민·결제정보는 담지 않는다.

가상계좌처럼 몇 시간 뒤에 입금하거나 결제 앱 전환으로 브라우저 맥락이 바뀌면 복귀 화면이 저장된 주소를 찾지 못할 수 있다. 이때 복귀 화면은 빈 화면으로 끝내지 않고 주문번호와 복구 방법을 안내한다. 이메일 발송이 연결되면 구매 확인 메일로 주소를 다시 보내는 경로를 추가해야 한다.

## 3. 데이터베이스

`supabase/migrations/20260727000400_payment_foundation.sql`부터
`20260731000100_payment_launch_approval.sql`까지 파일명 순서대로 모두 적용한다.

이 마이그레이션들은 다음을 추가한다.

- 프리미엄 상품 코드와 과거 상품 호환성
- 회원·비회원 주문
- 결제 후 구매 리포트
- 알림 설정
- 관리자 판매 접수 스위치
- 계좌입금 주문의 입금자명·입금기한과 관리자 입금확인
- 페이앱 주문과 결제요청번호 조회
- 비회원 휴대폰 주문 복구
- 취소·환불 때 리포트 접근 철회
- 과거 배포와 호환되는 판매 개시 승인 열(현재 코드는 사용하지 않음)
- 결제사 거부 사유 기록(`payment_setup_events`, 서버 역할 전용)

마지막 마이그레이션은 과거 배포 호환용이며 현재 결제 개시 조건에는 사용하지 않는다.

## 4. 판매자·법률 출시 게이트

- 공개 상호, 대표자, 사업자등록번호
- 통신판매업 신고번호 또는 적용되는 예외 판단 근거
- 소비자에게 공개할 적법한 사업장·서비스 주소
- 대표 전화, 고객지원 이메일, 개인정보 담당 연락처
- 부가세 포함 여부, 제공 시점, 리포트 분량·범위
- 디지털 콘텐츠 제공 개시 동의와 청약철회 제한 방식
- 중복결제·오류·미제공·부분제공·취소·환불 절차
- 개인정보 처리 목적·항목·보유기간·위탁·국외이전·파기·권리행사 절차

현재 화면에서 상세 집주소는 제거되어 있다. 그러나 결제 판매를 공개하려면 전자상거래법상 적용되는 판매자 주소 고지를 적법한 공개 주소로 확정해야 한다. 주소를 숨긴 채 운영 결제를 여는 방식으로 해결할 수는 없다.

## 5. 운영 도메인과 배포

배포 대상은 Cloudflare Workers이며 `pnpm build:sites` 뒤 `wrangler deploy --config dist/server/wrangler.json`으로 올린다. `NEXT_PUBLIC_APP_URL`은 빌드 시점에 메타데이터로 굳으므로 배포할 도메인을 정한 뒤 빌드해야 한다.

1. 무료 호스팅의 운영 URL 또는 소유 도메인을 확정한다.
2. `NEXT_PUBLIC_APP_URL=https://운영도메인`, `APP_HTTPS_ONLY=true`를 설정한다.
3. Supabase Auth Site URL과 Redirect URL에 `https://운영도메인/auth/callback`을 추가한다.
4. Supabase 마이그레이션을 적용한다.
5. 페이앱 피드백 URL을 등록하고, 포트원을 쓰는 경우 운영 채널과 웹훅도 등록한다.
6. `ADMIN_EMAILS`와 운영 결제 키를 배포 환경에 입력한다.
7. 카드 소액 승인·취소, 카카오페이, 토스페이, 가상계좌 발급·실입금, 중복 웹훅, 비회원 리포트, 회원 마이페이지, 환불 철회를 테스트한다.
8. 모든 테스트를 통과한 뒤 관리자 페이지에서 ‘판매 개시 승인’과 ‘신규 결제 접수’를 켠다.
9. `/ko/admin` 의 결제 열림 상태가 ‘결제 열림’인지, `/api/health` 의 `payments` 가 `open` 인지 확인한다.

## 6. 아직 자동으로 끝낼 수 없는 외부 작업

- 페이앱 가입·판매자 심사와 결제수단별 노출 승인
- 포트원 가입 및 KPN 채널 계약·심사
- 카카오페이·토스페이 직접 노출 심사
- 실제 운영 키 발급
- 통신판매 및 판매자 공개정보 확정
- 메일 발송 사업자 계약과 발신 도메인 인증

이 항목은 사업자 본인 확인과 계약 동의가 필요하므로 코드만으로 우회하거나 자동 승인할 수 없다.
